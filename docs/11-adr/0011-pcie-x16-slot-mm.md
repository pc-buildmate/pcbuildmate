# ADR-0011 · 主板首个 PCIe x16 槽位字段 `pcieX16SlotMm`

- 状态：已采纳
- 影响：data（catalogue 填数）、ui（`Scene3d.kt`）、docs/03 §3.3（字段表，需批准后变更）
- 相关：docs/18-3d-coordinates.md §18.8 #2/#3、docs/03-rules.md §3.3

## 背景

3D 间隙预览（docs/17、docs/18）用盒体表达「显卡是否超出机箱限长/限高」，为此需要知道显卡在主板上的槽位 Z 坐标。当前实现（`ui/.../preview/Scene3d.kt`）用两个常量近似：

- `FIRST_SLOT_FROM_IO_MM = 7.52`：第一个槽距 I/O 下缘 0.30 in，全板型统一；
- `GPU_SLOT_INDEX = 2`：显卡固定放第 2 槽。

即 `firstSlotZ = (boardHeight - IO_HEIGHT_MM) - 7.52`，再按槽距 20.32 逐槽下移。槽数则按 `formFactor` 推断。

但真实主板差异明显（docs/18 §18.8 待确认项 #2/#3）：

1. 首个 x16 槽位置不统一——部分板第一条 x16 是第 1 槽，部分是第 2 槽；
2. 首槽中心距板下沿的距离因板型/布局而异，并非所有板都等于「I/O 下缘 − 7.52」；
3. 显卡所在槽不应固定第 2 槽。

这些常量只能给近似值；答辩被追问「显卡槽位怎么定的」无法逐板回答。

## 决策

1. MOTHERBOARD 新增字段 `pcieX16SlotMm`（number，mm）：**第一个 PCIe x16 槽中心距板下沿（Z=0）的距离**；
2. MOTHERBOARD 新增可选字段 `pcieSlotCount`（number，个）：板载 PCIe 槽总数（含 x16 与 x1）；
3. 消费规则：`Scene3d.kt` 优先读 `pcieX16SlotMm` 作为首槽 Z；字段缺失（EMPTY）时回退现有常量估算；
   `pcieSlotCount` 缺失时回退 `formFactor` 推断；
4. 字段仅用于 3D 放置与提示，**不新增兼容规则**（保持 15 条规则不变）；如后续要接入规则，另写 ADR；
5. 数值来源：厂商规格页可标 `VERIFIED`，零售/新闻页标 `REPORTED`，不确定标 `EMPTY`。

## 后果

正面：

- 3D 的显卡槽位能按板差异精确放置，答辩可逐板回答来源；
- docs/18 §18.8 #2/#3 从「估算」收口为「按字段」。

负面：

- 每块主板多两个字段的采集成本；旧 demo 主板缺该字段时仍走估算回退；
- 字段名进入冻结表（docs/03 §3.3）后不可随意改，语义需一次定对。

## 替代方案

| 方案 | 为什么不选 |
|---|---|
| 继续用常量估算（现状） | 逐板差异无法表达；答辩追问无法回答 |
| 用 formFactor / chipset 推断首槽 | 同板型不同布局差异大，推断即猜测，违背「缺证据不猜测」 |
| 只加 `pcieX16SlotMm`，不加 `pcieSlotCount` | 槽数仍靠 formFactor 推断，Mini-ITX / 特殊板不准 |

## 复核触发条件

- 需要把首槽位置接入兼容规则（如「显卡顶到内存/散热」）时；
- 出现 `pcieX16SlotMm` 无法表达的需求（如多 x16 槽、异形槽位）时。

## 答辩口径

「3D 里显卡放在哪个槽、距板下沿多少，来自目录里主板字段 `pcieX16SlotMm`；
缺该字段的主板回退到 ATX 图纸的 0.30 in 常量，并在界面标注为估算。」

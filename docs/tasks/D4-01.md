# D4-01 · 预算推荐

> 状态：**done**（2026-11-05）｜认领：@MoeField｜预估：2–3 天｜依赖：D1 / D3

## 目标

`(预算, 用途, 偏好) -> 可编辑的起始配置`。权重可见、可解释；预算不够时给出结构化 shortfall，不假装成功。

## 现状

Entry 目前只有一个“载入 7800 演示配置”按钮；推荐算法与权重都还没写。

## 输入 / 输出

```kotlin
interface BudgetRecommenderPort {
    fun recommend(request: RecommendationRequest): RecommendationResult
}
```

`RecommendationResult` 已在 `contracts/Suggestions.kt`：`feasible / build / shortfallCny / relaxedPreferences / weightsVisible`。

## 实现要点

1. 按 `UseCase` 给 8 个类目分配预算权重（GAMING 偏 GPU，STUDY_OFFICE 偏 CPU/内存/存储）；
2. 每个类目在目录内选候选，先过硬约束（用 `CompatibilityEvaluator` 过滤），再按价格/偏好排序；
3. 总价不得超预算；不可行时 `feasible=false`，`shortfallCny>0`，返回最接近的自洽配置；
4. 所有排序稳定，权重合计为 1，`weightsVisible` 与实际分配一致。

## 验收

```bash
./gradlew :domain:recommend:test
```

- 8000/GAMING 能生成完整 8 类配置；
- 3000/GAMING 不可行，shortfall > 0；
- 权重可见且合计为 1；
- 同输入两次结果相同；
- 不引入 FPS / 跑分 / performance band。

## 不要做

- 不承诺“全局最优”；
- 不接实时价格/库存；
- 不在 UI 里算推荐。

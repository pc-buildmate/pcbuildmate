## 4. 建议的 API（必须与测试一致）

```kotlin
data class DiagnosisContext(
    val build: Build?,
    val revision: BuildRevision?,
    val diagnosis: Diagnosis?,
)

object DiagnosisMachine {
    fun transition(
        state: DiagnosisState,
        event: DiagnosisEvent,
        ctx: DiagnosisContext,
    ): TransitionResult<DiagnosisState>
}

data class ReplacementGuard(
    val currentRevisionId: Long?,
    val diagnosis: Diagnosis?,
    val candidateIds: Set<String>,
)

object ReplacementMachine {
    fun transition(
        state: ReplacementState,
        event: ReplacementEvent,
        guard: ReplacementGuard,
    ): TransitionResult<ReplacementState>
}
```

## 5. 关键约束

- Effects 顺序必须与 docs/04 表格一致；
- `Running` 收到不匹配 revision 的完成/失败 -> 丢弃，状态不变、无 rejection；
- `CandidatesLoaded` base 不匹配 -> Idle，静默丢弃，无 rejection；
- `Previewing` 里只有 `PreviewBuilt` 写入 `previewRevisionId`；
- `Apply` 先查 base 过期，再查 preview 是否就绪；
- `RecheckCompleted` 只有在 `rev.id == previewRevisionId` 时处理；有新 Conflict -> `Candidates(新 ctx)` + `LoadCandidates`，无 Conflict -> `Applied` + `PersistApplied`；
- 拒绝用 `Rejection(reason, textKey)`，key 映射见 `contracts/Workspace.kt` 新增的 `INVALID_STATE` / `PREVIEW_NOT_READY`。

## 4. 输出契约

- 空 revision → 空列表；
- 部件缺失 / 类别不匹配 → `Unverified(MISSING_FIELD, missingField=null, weakest=VERIFIED)`；
- 字段 EMPTY / 缺失 → `Unverified(MISSING_FIELD, missingField=FieldRef)`；
- `conflict=true` → `Unverified(SOURCE_CONFLICT)`；
- 数值解析失败 → `Unverified(INSUFFICIENT_DATA)`；
- `conflictId = ruleId:left.componentId.left.path:right.componentId.right.path`，PER_ITEM 追加 `#index`；
- PSU 走冻结公式 `ceil((cpu.tdpW + gpu.tdpW + 100) * 1.2)`。

## 7. 已知偏差 / 下一轮

- `PER_ITEM`（多套内存）没有 fixture 覆盖；实现已按 `#index` 生成，但需要补单测。
- `SOURCE_CONFLICT` 没有 fixture；实现已按 `weakestOfSources` 处理，但需要补单测。
- PSU 公式的 `conflictId` 右引用暂用 CPU.tdpW；若 UI 需要更精确的“公式冲突”引用，走契约变更。
- `count/SUM` 的 `leftValue` 用求和值，符合 §3.4.1；但多件右侧只取第一件，首版目录假设每类最多一件（内存 PER_ITEM 除外）。
